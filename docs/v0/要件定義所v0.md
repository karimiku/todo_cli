# 要件定義書 v0.2 — Terminal-First Todo CLI

## 1. 背景・目的
- ブラウザを開かず、思いついた瞬間に登録できる超軽量 Todo を提供する。
- 期日や締切は扱わず、「今日いまやる順番」だけに集中する体験を目指す。
- （将来拡張）右上常駐ウィジェットで視認性とワンクリック操作を実現する。

## 2. スコープ
### 対象
- 単体 CLI（バイナリ名: `todo`）。
- 互換エイリアス: `tb`（必須）、`td`（任意）。
- ローカル保存のみ／オフライン完結。
- 順序厳守: 完了は常に先頭タスクのみ（`next`）。ID 直指定での完了は行わない。

### 非スコープ（MVP）
- 期日、繰り返し、タグ、通知、同期、共有、サブタスク、添付、リッチテキスト。

## 3. ユースケース
- 即追加: `todo add <text>`
- 順序確認: `todo list`
- 先頭を完了: `todo next`
- 緊急差し込み: `todo focus <id>`
- 任意の並べ替え: `todo move <id> <pos>`
- 誤登録の削除: `todo delete <id>`
- 文言修正: `todo edit <id> <text>`

## 4. コマンド仕様（MVP）
| コマンド | 期待挙動 |
| --- | --- |
| `todo add <text>` | 未完了リストの末尾に追加する |
| `todo list` | 未完了タスクを 1 始まりで番号表示し、完了タスクを別枠表示する |
| `todo next` | 先頭タスクを完了状態（[✅]）にする ／ 削除はしない |
| `todo focus <id>` | 指定 ID のタスクを最優先に移動する |
| `todo move <id> <pos>` | 指定タスクを `<pos>` 番目へ移動する（1..N） |
| `todo delete <id>` | 未完了タスクを物理削除する |
| `todo edit <id> <text>` | 未完了タスクの本文を更新する |

### 4.1 コマンド共通ルール
- ID は表示中の未完了リストの順位（1..N）。
- 完了済みタスクには番号を付けず、`[✅]` で別枠表示する。
- 範囲外 ID はエラー。「未完了の件数は N 件です」を返す。
- `move` の `<pos>` が N を超える場合は N に丸め、1 未満はエラー「順位は 1 以上を指定してください」。
- `edit` の空文字（trim 後）はエラー「空のテキストは不可」。

### 4.2 コマンド別詳細要件
#### focus `<id>`
- 1..N の ID を受け取り該当タスクを最上位へ移動する。
- 指定 ID が 1 の場合は順序変更せず成功とみなし、`updated_at` の更新と成功メッセージのみを返す。
- 未完了が 0 件、または ID が範囲外の場合は「未完了の件数は N 件です」を返す。
- 成功メッセージ: `⇡ 最優先に移動: <text>`

#### move `<id> <pos>`
- 1..N の ID を指定順位 `<pos>` (1..N) に移動する。
- `<pos>` が N 超過なら N、1 未満ならエラー。
- 現在位置と `<pos>` が同じ場合も成功扱い。メッセージは `⇄ 順番変更: <text> → <pos>`。
- 範囲外 ID や `<pos>` の指定ミス時は focus と同じエラーを返す。

#### edit `<id> <text>`
- 1..N の ID を受け取り本文を上書きする。
- 前後の空白を除去した結果が空の場合はエラー「空のテキストは不可」。
- 順序・ステータスは変えない。成功メッセージは `✎ 更新: <text>`。

#### delete `<id>`
- 1..N の ID を受け取り未完了タスクを物理削除する。
- 削除後はリストに即時反映し、成功メッセージは `🗑 削除: <text>`。
- 未完了 0 件や範囲外 ID は focus と同じエラーを返す。

#### エイリアス `tb` / `td`
- `todo` と同一挙動で全コマンドを提供する。
- `help`／`usage` でもエイリアス名を案内する。

## 5. 表示仕様
```
$ todo list
1 メール返信
2 図書館に本返却
3 買い出し

---

[✅] 会議メモ整理
```
- 未完了タスクは操作ごとに再採番する。
- 完了タスクは下段に `[✅]` のみで表示する。

## 6. 順序・操作ルール
- 追加 (`add`) は常に末尾。
- 完了 (`next`) は先頭 1 件のみ（順序厳守）。
- 差し込み (`focus`) は `move <id> 1` のショートカット。
- 並べ替え (`move`) は未完了内の相対順位を書き換える。
- `delete` / `edit` は未完了タスクのみ対象（完了済みは対象外）。

## 7. データ要件
### 内部モデル（例）
```
Task {
  text        string
  done        bool
  order       float64
  createdAt   time.Time
  updatedAt   time.Time
}
```
- `order` は並び順キー。表示 ID は都度計算（1..N）。

### 永続化
- SQLite（純 Go ドライバ `github.com/glebarez/sqlite`）。
- 保存先: `~/.config/todo/todo.db`（`TODO_HOME` があれば `TODO_HOME/todo.db`）。
- 初期化時に `PRAGMA journal_mode=WAL`、`synchronous=NORMAL`、`busy_timeout=4000` を適用。
- DB ファイルは権限 600/644 で生成し、外部送信は行わない。

### `order_key` の扱い
- 追加時は未完了の最大 `order_key + 1.0` を採用。
- `focus` / `move` は `order_key` を直接更新し再ソートする。`move` の `<pos>` が N 超過なら N、1 未満はエラー。
- ギャップが極端に小さい場合は normalize 処理で 1.0 刻みに再採番する。

## 8. 非機能要件
- 起動 → 登録／完了までの体感 < 300ms（M1/M2 相当マシン）。
- 単一バイナリ（目標 < 15MB）。
- 依存最小（標準ライブラリ優先）。
- ログ／テレメトリなし。ネットワーク通信なし（常時オフライン可）。

## 9. ウィジェット（拡張: v0.2 想定）
- SwiftBar/xbar 連携による `todo bar` を想定。
- 1 行目: 先頭タスクを強調表示、クリックで `next` 実行＆再描画。
- 2 行目以降: 上位タスクを表示、クリックで `focus <id>`。
- 目的: 右上常駐で「見る → 次を片付ける」を 1 クリック化。

## 10. エラーハンドリング・メッセージ方針
- 入力不足・範囲外は日本語で明示（例: 「未完了の件数は N 件です」）。
- `next` で未完了 0 件: 「未完了はありません 🎉」。
- メッセージは操作の動詞 + 対象タスクで表現。
- `usage:` は短くシンプルに提示する。

## 11. セキュリティ／プライバシ
- ローカル保存のみ。外部送信なし。
- 保存ディレクトリはユーザーディレクトリ配下、権限 600/644 程度を維持する。

## 12. インストール／互換
- バイナリ名: `todo`。
- 必須エイリアス: `tb`（ドキュメントに設定例を掲載）。
- 任意エイリアス: `td`。
- データパスは共通（`todo` / `tb` で分裂しない）。

## 13. 受け入れ基準（例）
### 正常系
1. `add` → `list` で末尾に追加され、1..N の番号が付く。
2. `next` 実行で先頭タスクが `[✅]` セクションに移動する。
3. `focus 2` で 2 番のタスクが 1 番になり、「⇡ 最優先に移動: <text>」を表示する。
4. `move 3 10` で対象タスクが末尾へ移動し、「⇄ 順番変更: <text> → <pos>」を表示する。
5. `edit 2 ...` で本文が置き換わり、「✎ 更新: ...」を表示する。
6. `delete 1` で対象未完了が削除され、「🗑 削除: <text>」を表示する。
7. `tb list`、`td list` が `todo list` と同一出力になる。

### 異常系
1. `focus 5`（未完了 3 件）で「未完了の件数は 3 件です」と表示し、順序は変わらない。
2. `move 1 0` で「順位は 1 以上を指定してください」と表示し、順序は変わらない。
3. `edit 1 "   "` で「空のテキストは不可」と表示し、本文は変わらない。
4. 未完了 0 件で `next` 実行時に「未完了はありません 🎉」を表示する。

## 14. 将来拡張（参考）
- `purge`: 完了タスクの一括削除。
- `undo`: 直前操作の取り消し。
- FTS 検索、エクスポート（JSON/NDJSON）、バックアップ。
- 常駐ウィジェットでの静的クリック処理（`terminal=false`）。
