# 要件定義書 v2 - AI 統合 & インタラクティブ表示

## 1. 目的（v1 からの追加）

AI アシスタント（ClaudeCode 等）との連携を強化し、長文タスクの管理を快適にする。

### 背景

- AI が提案する作業内容を詳細に保存したい
- 長文の Markdown ドキュメントをタスクとして管理したい
- 通常のリスト表示では長文が見づらい
- AI が構造化データとして todo を読み取りたい
- スクリプトから静かにタスクを追加したい

## 2. スコープ（v2 で追加する機能）

### 2.1 コア機能

| 機能 | 優先度 | 説明 |
|------|--------|------|
| **要約表示** | 必須 | `todo list` で長文の最初の行のみ表示 |
| **インタラクティブ表示** | 必須 | `todo list -d` で vim 風の詳細確認 |
| **Markdown レンダリング** | 必須 | 詳細表示時に Markdown を美しく表示 |
| **JSON 出力** | 必須 | `todo list --json` で構造化データ出力 |
| **静かな追加** | 必須 | `todo add --quiet` で出力を抑制 |
| **標準入力対応** | 必須 | パイプでタスクを追加 |
| **緊急追加** | 推奨 | `todo add --urgent` で先頭に追加 |

### 2.2 インタラクティブモードの仕様

#### 起動方法

```bash
todo list -d
# または
todo list --detail
```

#### 画面構成

```
┌─────────────────────────────────────────────┐
│ 上部: タスクリスト（30-40%）                │
│ - 番号付きリスト                            │
│ - カーソル位置表示（▶）                     │
│ - 要約のみ表示                              │
├─────────────────────────────────────────────┤
│ 下部: プレビューエリア（60-70%）            │
│ - 選択中のタスクの詳細                      │
│ - Markdown レンダリング済み                 │
│ - スクロール可能                            │
└─────────────────────────────────────────────┘
```

#### キーバインド

| キー | リスト選択モード | 詳細表示モード |
|------|-----------------|---------------|
| `j` | 次のタスクへ | 下にスクロール |
| `k` | 前のタスクへ | 上にスクロール |
| `Enter` | 詳細を全画面表示 | - |
| `q` | 終了 | リスト選択に戻る |
| `gg` | - | 先頭へジャンプ |
| `G` | - | 末尾へジャンプ |
| `Ctrl+C` | 強制終了 | 強制終了 |

#### 表示ルール

1. **リスト表示**
   - 各タスクの最初の行のみ表示
   - Markdown ヘッダー記号（`#`, `##`）は除去
   - 最大60文字まで、超過は `…` で省略

2. **プレビュー表示**
   - Markdown を色付きでレンダリング
   - コードブロックはシンタックスハイライト
   - チェックボックスは `☐` / `☑` で表示
   - 見出しは太字・色付き

3. **詳細表示（全画面）**
   - Enter キーで切り替え
   - Markdown レンダリング
   - j/k でスクロール
   - q でリスト選択に戻る

### 2.3 JSON 出力の仕様

```json
{
  "pending": [
    {
      "id": 1,
      "text": "タスクの全文（Markdown含む）",
      "is_done": false,
      "order_key": 1.0,
      "created_at": "2026-01-15T10:00:00Z",
      "updated_at": "2026-01-15T10:00:00Z"
    }
  ],
  "completed": [
    {
      "id": 2,
      "text": "完了済みタスク",
      "is_done": true,
      "order_key": 1.0,
      "created_at": "2026-01-14T10:00:00Z",
      "updated_at": "2026-01-15T09:00:00Z"
    }
  ],
  "count": {
    "pending": 1,
    "completed": 1
  }
}
```

#### 使用例

```bash
# AI が先頭タスクを確認
todo list --json | jq '.pending[0].text'

# 未完タスク数を取得
todo list --json | jq '.count.pending'

# 全タスクをループ処理
todo list --json | jq -r '.pending[] | "\(.id): \(.text)"'
```

### 2.4 静かな追加モードの仕様

```bash
# 通常
todo add "タスク"
# 出力: 追加: タスク

# 静かなモード
todo add "タスク" --quiet
# 出力なし（エラー時のみ標準エラーに出力）

# エイリアス
todo add "タスク" -q
```

#### 使用例

```bash
# スクリプトから使用
for task in "${tasks[@]}"; do
  echo "$task" | todo add --quiet
done

# AI からの使用
echo "詳細なタスク内容..." | todo add --quiet
```

### 2.5 標準入力対応

```bash
# パイプで追加
echo "タスク内容" | todo add

# ヒアドキュメント
todo add <<EOF
# データベース最適化

## 背景
検索が遅い

## 実施内容
1. インデックス追加
2. クエリ最適化
EOF

# ファイルから読み込み
cat task.md | todo add --quiet
```

### 2.6 緊急追加モード

```bash
# 先頭に追加
todo add "本番障害対応" --urgent

# 既存タスクを緊急化（focus と同じ）
todo focus 3
```

## 3. 非スコープ（v2 ではやらない）

- タスクの検索機能（`/` キー）
- タスクのフィルタリング
- タグ機能
- 期限・日付管理
- 複数選択・一括操作
- エディタ統合（`--edit` フラグ）
- 外部ツール連携（fzf, glow）→ Pure Go 実装のみ
- 他 OS のステータスバー対応

## 4. データ・実装方針

### 4.1 DB スキーマ

- **変更なし**（v0/v1 と同じスキーマを使用）
- `text` フィールドに Markdown を含む長文を保存可能
- 既存のタスクとの互換性を維持

### 4.2 技術スタック

| 機能 | ライブラリ |
|------|-----------|
| TUI フレームワーク | `github.com/charmbracelet/bubbletea` |
| UI コンポーネント | `github.com/charmbracelet/bubbles` |
| Markdown レンダリング | `github.com/charmbracelet/glamour` |
| スタイリング | `github.com/charmbracelet/lipgloss` |

### 4.3 後方互換性

- 既存のコマンドは**すべて動作を維持**
- 新しいフラグを使わない限り、既存の動作と同じ
- データベースのマイグレーションは不要

## 5. 非機能要件

| 項目 | 目標値 | 測定方法 |
|------|--------|---------|
| `todo list` 起動時間 | < 100ms | time コマンド |
| `todo list -d` 起動時間 | < 300ms | time コマンド |
| JSON 出力時間 | < 50ms | time コマンド |
| Markdown レンダリング | < 100ms | 体感 |
| キー入力の反応 | < 50ms | 体感 |

### パフォーマンス配慮

- インタラクティブモードは必要時のみ起動
- Markdown レンダリングは表示時のみ実行
- JSON 出力は軽量な SQL クエリのみ

sudo cp todo /usr/local/bin/

### 6.3 AI 連携の設定例

ClaudeCode の場合、特別な設定は不要。以下のコマンドが使えることを確認：

```bash
# JSON 出力テスト

# 静かな追加テスト
echo "テストタスク" | todo add --quiet

# インタラクティブモードテスト

```

## 8. リスク/対応

| リスク | 影響 | 対応策 |
|--------|------|--------|
| TUI ライブラリの学習コスト | 開発遅延 | サンプルコードを参考に段階的実装 |
| Markdown レンダリングのパフォーマンス | 体感速度低下 | キャッシュ、遅延レンダリング |
| ターミナルサイズの多様性 | 表示崩れ | レスポンシブ対応、最小サイズ制限 |
| 長文タスクのメモリ消費 | メモリ不足 | 表示範囲の制限、ページング |
| JSON 出力のエスケープ処理 | パース失敗 | 標準ライブラリの使用 |
