要件定義書（v0.2）— ターミナル特化 Todo CLI

1. 背景・目的

ブラウザ等を開かず思いついた瞬間に登録 → 順番通りに処理できる超軽量 Todo。

日付や締切は扱わず、「今日いまやる順番」だけに集中。

右上ウィジェット（後述）で常時視認・ワンクリック操作を目指す。

2. スコープ

単体 CLI（バイナリ名：todo）。

互換エイリアス：tb（必須）、td（任意）。

ローカル保存のみ／オフライン完結。

順序厳守：完了は常に先頭のみ（next）。ID 直指定での完了は行わない。

非スコープ（MVP）

期日/繰り返し/タグ/通知/同期/共有/サブタスク/添付/リッチテキスト。

3. ユースケース

即追加：todo add <text>

順序確認：todo list（上から順に番号付与）

先頭を片付け：todo next（削除せずチェック済みに変更）

緊急差し込み：todo focus <id>（=一番上へ移動）

任意の並べ替え：todo move <id> <pos>

間違い削除：todo delete <id>

文言修正：todo edit <id> <text>

4. コマンド仕様（MVP）
   todo add <text> # 末尾に追加
   todo list # 未完了を上から順に番号表示（1 始まり）
   todo next # 一番上（=1）を完了にする（削除しない）
   todo focus <id> # <id> を一番上へ（=最優先）
   todo move <id> <pos> # <id> を <pos> 番へ（1 が最上位）
   todo delete <id> # 未完了から物理削除
   todo edit <id> <text> # 未完了の文言編集

ID の意味：表示中の未完了リストでの現在の順位（1..N）。
完了済みは番号を付けず、[x]で別枠表示。

エラー系：

範囲外 ID（id>未完了件数）はエラー表示。

move の pos>N は N に丸め。

空テキスト編集はエラー。

4.1 拡張コマンド詳細要件

focus <id>
- 1..N の ID を受け取り該当タスクを最上位へ移動する。既に 1 番の場合は順序変更なしで成功扱いとし、list は再採番された順序を表示する。
- 成功時は「⇡ 最優先に移動: <text>」を返す。未完了が 0 件、または ID が範囲外のときは処理せず「未完了の件数は N 件です」を返す。
- 完了済みタスクは対象外（list に番号が付かないため指定不可）。

move <id> <pos>
- 1..N の ID を受け取り、指定順位 <pos> (1..N) に移動する。<pos> が N を超える場合は N、1 未満はエラー「順位は 1 以上を指定してください」を返す。
- 対象と同じ順位を指定した場合は順序変更なしで成功メッセージ「⇄ 順番変更: <text> → <pos>」を返す。
- 範囲外 ID や pos の指定ミスは focus と同じエラーメッセージを返す。

edit <id> <text>
- 1..N の ID を受け取り本文を置き換える。前後の空白を除いた結果が空の場合はエラー「空のテキストは不可」。
- 順序と完了状態は変えず、成功時は「✎ 更新: <text>」を返す。変更履歴や undo は提供しない。

delete <id>
- 1..N の ID を受け取り未完了タスクを物理削除する。
- 削除後は再採番されたリストに即時反映し、成功時は「🗑 削除: <text>」を返す。未完了 0 件や範囲外 ID は focus と同じエラーを返す。

tb/td エイリアス
- todo と同一挙動で全コマンドを提供する。help/usage でもエイリアス名を案内する。

5. 表示仕様

todo list 出力例

1 メール返信
2 図書館に本返却
3 買い出し

---

[x] 会議メモ整理

番号は未完了のみに毎回再採番。完了は下段に [x] のみ。

6. 順序・操作ルール

追加は常に末尾。

next は先頭 1 件のみ完了（順序厳守）。

focus は指定 ID を一番上へ（move <id> 1 のショートカット）。

move は未完了内の相対順位を書き換え。

delete/edit は未完了に対してのみ。完了済みは対象外（MVP）。

7. データ要件

内部モデル（例）

Task{text, done, order, createdAt, updatedAt}

order は並び順キー（float 等）。表示 ID は都度計算（1..N）。

永続化

MVP：SQLite（純 Go ドライバ github.com/glebarez/sqlite を利用）
- 保存先: ~/.config/todo/todo.db（環境変数 TODO_HOME があれば TODO_HOME/todo.db）
- 初期化時に WAL / synchronous=NORMAL / busy_timeout=4000 等の PRAGMA を適用
- DB ファイルは 600/644 権限で生成し、外部送信は行わない

order_key の扱い
- 追加時は未完了の最大 order_key + 1.0 を採用する。
- focus/move は order_key を直接更新して再ソートし、move pos>N は N に丸める。pos<1 はエラー。
- ギャップが極端に小さくなった場合は normalize サブルーチンで 1.0 刻みに再採番し、精度劣化を防ぐ。

8. 非機能要件

起動 → 登録/完了の体感 < 300ms（M1/M2 級）。

単一バイナリ（目標 < 15MB）。

依存最小（標準ライブラリ優先）。

ログ/テレメトリなし。ネットワーク通信なし（常時オフライン可）。

9. ウィジェット（拡張：v0.2 想定）

SwiftBar/xbar 連携：todo bar

1 行目：先頭タスクを強調表示、クリック＝ next 実行・即再描画。

2 行目以降：上位数件、クリック＝ focus <id>。

目的：右上常駐で「見る → 次を片付ける」を 1 クリックに短縮。

10. エラーハンドリング・メッセージ方針

入力不足/範囲外は日本語で即明示（例：「未完了の件数は N 件です」）。

next で未完了 0 件のとき：「未完了はありません 🎉」。

コマンド名や使い方は usage: で短く提示。成功メッセージは操作の動詞 + 対象タスクを含める。

11. セキュリティ/プライバシ

ローカル保存のみ。外部送信なし。

権限：ユーザーディレクトリ配下、600/644 程度で保存。

12. インストール/互換

バイナリ名：todo。

必須エイリアス：tb（.zshrc 等で同梱ドキュメント記載）。

任意エイリアス：td。

データパスは共通（todo/tb で分裂しない）。

13. 受け入れ基準（例）

正常系
- add→list で末尾に追加され、1..N の番号が付く。
- next 実行で先頭 1 件が [x] に降りる／未完了から消える（物理削除されない）。
- focus 2 で「2 番」の内容が 1 番になり、メッセージ「⇡ 最優先に移動: <text>」を表示する。
- move 3 10 で対象タスクが末尾へ移動し、成功メッセージ「⇄ 順番変更: <text> → <pos>」が表示される。
- edit 2 メールを確認して返信 で 2 番の本文が置き換わり、「✎ 更新: メールを確認して返信」と表示される。
- delete 1 実行で対象未完了がリストから消え、「🗑 削除: <text>」を表示する。
- tb list、td list で todo list と同一出力になる。

異常系
- focus 5（未完了 3 件）で「未完了の件数は 3 件です」と表示され、順序は変わらない。
- move 1 0 で「順位は 1 以上を指定してください」と表示され、順序は変わらない。
- edit 1 "   " で「空のテキストは不可」と表示され、本文は変わらない。
- next 実行時に未完了 0 件なら「未完了はありません 🎉」を表示する。
