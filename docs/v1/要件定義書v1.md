要件定義書 v1（差分）— Head-Only 常時表示

1. 目的（v0 からの追加点のみ）

右上メニューバー等に先頭タスク 1 件だけを常時表示。

表示行のクリック 1 回で next 実行し、即座に次のタスクへ自動切替。

2. スコープ（v1 で増えるもの）

新サブコマンド：todo bar --head-only [--maxlen N] [--icon STR]

対応環境：macOS + SwiftBar/xbar（MVP）。
※CLI での追加・並べ替え・完了は引き続き v0 のコマンドを使用（再掲不要）。

非スコープ（v1 ではやらない）

タスク複数表示のドロップダウン、検索/Undo、配布（brew/Docker）、他 OS の常時表示。

3. 仕様（bar／head-only）
   3.1 表示ルール

先頭タスク 1 件のみをタイトル行に表示。例：
▶️ メール返信…

文字数は --maxlen で省略（既定 28 〜 32 目安）。超過は …。
全文は tooltip に出す（任意）。

未完が 0 件のとき：🎉 空っぽ！（クリック不可）。

3.2 クリック挙動

タイトル行クリック＝ todo next を実行。
xbar/SwiftBar パラメータ例：bash=todo param1=next terminal=false refresh=1
→ 実行直後に再描画し、次の先頭を表示。

3.3 オプション

--head-only（必須）：1 件のみ出力（デフォ挙動に固定）

--maxlen N：表示最大文字数（省略時は実装既定）

--icon STR：先頭アイコン（例：▶️ / ✅ / 🔥）

3.4 SwiftBar プラグイン要件（ユーザー手元の設定）

ファイル例：todo-next.2s.sh（実行権限付与、中身は todo bar --head-only）

リフレッシュ間隔：2–5 秒推奨。

4. データ・実装方針の差分

DB スキーマ変更なし（v0 のまま）。

todo bar は未完の最小 order_key を 1 件だけ読む軽量クエリ。

多重クリック対策：next はトランザクション＋ busy_timeout で二重完了防止。

失敗時はタイトルに ⚠︎ Error、詳細は tooltip（短文）。

5. 非機能要件（追加）

todo bar 実行時間：≤ 100ms 目標（上位 1 件＋軽い集計のみ）。

電池/負荷配慮：2–5 秒更新でも CPU 使用率が目立たないこと。

6. セットアップ導線（追加）

todo を PATH に配置（v0 と同じ）。

SwiftBar 導入。

todo-next.2s.sh をプラグインフォルダに作成：

#!/bin/zsh
todo bar --head-only --maxlen 28 --icon "▶️"

chmod +x 後、SwiftBar で有効化。

7. 受け入れ基準（v1 差分）

メニューバーに常時 1 件のみが表示される。

クリックで即 next が実行され、表示が次のタスクへ切り替わる。

todo list の 1 番とメニューバー表示が常に一致。

未完 0 件では**“空っぽ”表示**になり、クリックしても動作しない。

連打や並列起動でも二重完了や順序破壊が起きない。

8. リスク/対応（v1 特有）

長文タイトルの可読性：--maxlen で省略＋ tooltip で補完。

order_key の劣化：将来的に normalize を導入（v1 範囲外）。

macOS 依存：他 OS の常時表示は v1.1 以降（Waybar/Rainmeter 等）。
