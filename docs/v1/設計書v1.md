# 設計書 v1.0 — Head-Only 常時表示

## 1. 目的 / 前提
- 右上メニューバー（macOS）に未完タスクの先頭 1 件だけを常時表示する。
- タイトル行をクリックすると `todo next` が即時実行され、次のタスクへ切り替わる体験を提供する。
- 対象プラットフォーム: macOS（SwiftBar / xbar）。
- CLI の追加・並べ替え・完了ロジックは v0 と同じものを利用し、DB スキーマ変更は行わない。

## 2. 外部仕様
### 2.1 サブコマンド
```
todo bar --head-only [--maxlen N] [--icon STR] [--no-tooltip]
```
| オプション | 既定値 | 説明 |
| --- | --- | --- |
| `--head-only` | 必須 | 先頭 1 件のみを表示対象にするフラグ（他モード導入時との将来互換用）。 |
| `--maxlen N` | 28 | タイトルの最大文字数。超過時は末尾に `…` を付与する。 |
| `--icon STR` | `▶️` | タイトル先頭に付けるアイコン文字列。 |
| `--no-tooltip` | 無し | 指定時は tooltip 出力を抑止する（未指定なら全文 tooltip を出力）。 |

### 2.2 SwiftBar / xbar 出力フォーマット
| 状態 | 出力例 |
| --- | --- |
| 未完タスクあり | `▶️ メール返信をする… | tooltip=クリックで完了 bash=todo param1=next terminal=false refresh=1` |
| 未完タスクなし | `🎉 空っぽ！ | tooltip=おつかれさま` |
| エラー発生 | `⚠︎ Error | tooltip=DB busy` |

- クリックアクションは `bash=todo param1=next terminal=false refresh=1`。SwiftBar は実行後に再描画し、次のタスクを即表示する。

## 3. SwiftBar 連携手順
- プラグイン例: `~/Library/Application Support/SwiftBar/Plugins/todo-next.2s.sh`
  ```bash
  #!/bin/zsh
  todo bar --head-only --maxlen 28 --icon "▶️"
  ```
- 実行権限: `chmod +x` を付与。
- 更新間隔: 2〜5 秒を推奨。

## 4. 内部構成
### 4.1 表示データ取得
1. v0 と同じ手順で SQLite に接続（WAL / `busy_timeout` / トランザクション）。
2. 未完了の先頭 1 件を取得。
   ```sql
   SELECT id, text
   FROM tasks
   WHERE is_done = 0
   ORDER BY order_key ASC, id ASC
   LIMIT 1;
   ```
3. 結果が存在すれば文字列整形へ進み、存在しなければ空表示を返す。

### 4.2 文字列整形
- `--icon` を先頭に付与し、`--maxlen`（UTF-8 セーフな rune ベース）で省略し末尾に `…` を付ける。
- `--no-tooltip` 指定が無い場合は tooltip に全文を入れる。
- xbar フォーマットのキー／値は以下を利用する。
  - `tooltip=<全文>`
  - `bash=todo`
  - `param1=next`
  - `terminal=false`
  - `refresh=1`

### 4.3 `next` との連携
- 実際の完了処理は v0 の `next` コマンドをそのまま使用。
- 多重クリック／並列実行に備え、SQL 側で単一行のみを完了させる。
  ```sql
  WITH first AS (
    SELECT id
    FROM tasks
    WHERE is_done = 0
    ORDER BY order_key, id
    LIMIT 1
  )
  UPDATE tasks
  SET is_done = 1,
      updated_at = CURRENT_TIMESTAMP
  WHERE id = (SELECT id FROM first);
  ```
- `RowsAffected == 1` の場合のみ成功とみなし、0 の場合は競合が発生したため無視する。

## 5. エラー処理
| 状況 | タイトル表示 | tooltip | クリック | 補足 |
| --- | --- | --- | --- | --- |
| DB 接続/クエリ失敗 | `⚠︎ Error` | 短文理由（例: `DB busy`） | 無効 | `bash` キーは出力しない |
| 未完タスク 0 件 | `🎉 空っぽ！` | `おつかれさま` | 無効 | タスクが追加されるまで静的表示 |
| 正常タスク | `▶️ ...` | 全文 | `todo next` | `--no-tooltip` 指定時は tooltip 省略 |

- `busy_timeout` により多くのロック競合は自動でリトライ。最終的に失敗した場合にのみ Error を表示。

## 6. 非機能要件
- `todo bar` の単発実行時間: 100ms 以内（M1/M2 クラス）。
- SwiftBar 更新間隔 2〜5 秒時に CPU 利用率 1〜2% 未満を想定。
- デフォルトでログなし。`TODO_LOG=1` で stderr にデバッグログを出力。

## 7. テスト戦略
### 7.1 ユニットテスト
- 文字列省略: 全角・結合文字・絵文字を含むケースで `--maxlen` が正しく働く。
- 出力キー検証: `bash` / `param1` / `terminal` / `refresh` が期待値通り。
- 未完 0 件時にクリックアクションが出力されないこと。

### 7.2 競合テスト
- `next` を並列実行し、`RowsAffected == 1` のみ成功、他は無効になることを確認。
- `busy_timeout` によりトランザクション衝突が解消されること。

### 7.3 パフォーマンステスト
- ローカル SQLite で `todo bar --head-only` を 100 回程度計測し、平均 100ms 以下を確認。

## 8. デプロイ / 運用
- v0 と同じ手順で `todo` バイナリをビルド・配置。
- SwiftBar プラグインを配置し、ポーリング間隔を設定。
- トラブルシュート手順:
  1. ターミナルで `todo list` が正常に動作するか確認。
  2. プラグインスクリプトを `bash -x` で実行し、標準出力を確認。

## 9. 互換性・マイグレーション
- DB スキーマ変更なし。v0 で作成した DB をそのまま利用する。
- `todo bar` を利用しない場合でも、既存コマンドは影響を受けない。

## 10. 既知の課題 / 将来対応
- `order_key` の細分化（劣化）が進んだ場合の normalize 処理は別バージョンで対応予定。
- 複数タスク表示モード、他 OS のステータスバー対応、Undo/Redo、FTS 検索、purge 等は今後のロードマップへ委ねる。
